FlowLM option 2: bucketed CPU int8 prompt prefill
Date: 2026-10-05
Branch: codex/flowlm-option-2-int8-prefill
Status: CPU int8 host parity passed for isolated buckets; Pixel 10 acceptance pending

Implementation
  Static, headless prefill signatures: P=16 (index 0), P=1 (1), P=8 (2);
  the fused one-step decode is index 3. The Android session chooses
  the largest bucket no larger than the real remaining token count. It copies
  only real K/V rows and preserves the voice prefix and absolute RoPE offsets.
  PocketTtsConfig.usePrefill remains false by default.
  FlowLmHarnessTest compares every prompt K/V row to sequential CPU int8,
  locates the first divergent layer/head, checks voice-prefix preservation and
  the first subsequent BOS/decode result, then saves a report even on failure.

Host validation
  Linux: WSL2, pinned pocket-tts clone 001cf6e, torch 2.12.1+cpu,
  litert-torch 0.9.3. Android LiteRT runtime: 2.2.0 (CPU prefill, no dispatch).
  A four-bucket P32 attempt emitted a 342,816,144-byte fp32 graph, then the
  old opcheck() allocated >13 GB while inspecting it. Metadata inspection
  without allocation succeeds, but a CompiledModel load of that graph peaked
  at 6,956,792 KiB RSS under an 8 GB process cap and printed XNNPACK runtime
  creation errors. The legacy P16 graph loaded at 708,156 KiB by the same
  method. P32 was removed from this experiment before int8 quantization;
  larger prompts use multiple P16 invocations. P32 int8 load is unmeasured.

  Three-bucket fp32 graph: 340,184,004 bytes. Eager P16/P8/P1 K/V maximum
  difference from sequential eager: 0 for each bucket. Metadata opcheck:
  no banned ops or >4D tensors. The fp16 byproduct could not finish under a
  10 GB virtual-memory cap. An explicit-index TFLite fp32 parity attempt
  also failed under the cap at XNNPACK tensor allocation. TFLite fp32 row
  parity is therefore unverified; this graph is a quantization intermediate.

  Three-bucket dynamic-range int8 graph: 89,402,224 bytes; SHA-256
  d7ee9bc3e9ef13fe82776e4d3825a6555f20e42338e4fe79b778458d04e84b25.
  CompiledModel.from_file peak RSS on WSL: 1,880,356 KiB under an 8 GB cap.
  CPU int8 P16/P8/P1 headless output versus sequential CPU int8: K and V
  max absolute difference 0.00e+00 for every real row (alba preset). The
  first fused int8 step versus eager fp32 had EOS max difference 6.56e-01,
  latent correlation 0.999813 / max difference 5.70e-02, K correlation
  0.999912 / max difference 9.50e-02, and V correlation 0.999164 / max
  difference 4.72e-02. These are quantization deltas, not prefill deltas.
  Python syntax and Android instrumentation compilation: PASS.
