Thread-count candidate
  PocketTtsConfig.lmCpuThreads configures the FlowLM CompiledModel CPU options
  alone. Null retains the LiteRT default. This is opt-in and leaves production
  settings unchanged.
  FlowLmHarnessTest.compareCpuThreadsPromptPaired runs A/B/B/A with a fresh
  model for each arm and records graph load, input/KV copy, compute, readback,
  first run, warm run per token, total prompt, graph checksum, device fingerprint,
  and paired output differences. Use promptTokens 4, 33, and near with alba and
  marius; near means PMAX - voiceLength - 1. Repeated source token IDs isolate
  prompt length from tokenizer differences. This is a prompt-only diagnostic.
  PowerBenchmarkTest.flowLmCpuThreadsPower runs a separate A/B/B/A full-pipeline
  experiment on the same graph and default decoder placement, seed 42. It
  records per-arm load, first audio, inference wall time, RTF, graph bytes,
  process PSS and cumulative RSS high water, thermal status, and PCM. Energy is
  the sum of CPU/GPU/TPU Android PowerMonitor deltas during synthesize+play,
  minus a duration-scaled PCM-only playback interval. It logs total incremental
  joules, joules per audio second, p50/p95 (n=2 per arm), and speed drift.
  flowLmText and flowLmVoice arguments apply to both synthesis and repeat
  measurement. Test short, medium, and compiled-in long PARAGRAPH text with two
  voices and 2/4/6 thread candidates. One instrumentation method per run.
  Listen to saved WAVs and confirm complete text before accepting any setting.
